# Tools, commands, expected output, and what was not run

Two parallel flows exist for both formal and UVM. Only SymbiYosys and Vivado xsim are installed here; the Cadence flows (JasperGold, Xcelium/IMC) were written
carefully from the vendor documentation but were **not executed** ("untested here"). The SystemVerilog is standard UVM 1.2 and avoids xsim-only constructs;
every tool difference lives in the scripts.

| flow | tool (assumed version) | status |
|---|---|---|
| formal | SymbiYosys + yosys 0.66 + yices/z3 + Berkeley ABC 1.01 via `verif/scripts/abc_wrap.sh` | RUN (all results in reports/formal_summary*.md) |
| formal | Cadence JasperGold (any release with `analyze -sv12`, `prove -all`; assumed 2023.x or newer) | UNTESTED HERE |
| UVM | Vivado xsim 2025.2, UVM 1.2 (`-L uvm`), gcc-built DPI `.so` | RUN |
| UVM | Cadence Xcelium (xrun 23.x/24.x), `-uvm -uvmhome CDNS-1.2`, IMC for coverage merge | UNTESTED HERE |

## 1. Formal with SymbiYosys (run)
* `verif/formal/gen_jobs.py` is the single source of every job; `verif/formal/run_formal.sh [--prefix] [--jobs "regs arb"] [--tasks "prove cover"] [-j N]` generates the `.sby`
  files (build/verif/formal/<fixed|prefix>/<job>/), runs all tasks in parallel and writes `verif/reports/formal_summary[_prefix].md`.
  Task kinds per job: `prove`/`bmc` (as listed), `cover` (same defines as the proof), `canary` (must FAIL), plus job specials (`mutant_nocrc` must FAIL).
* Expected output: every row `OK` in the summary (result column `PASS (OK)` / `FAIL (OK)` for canaries and mutants).
* Mutation sanity: `python3 verif/formal/mutate.py <job> <task> <dut.v relative to the RTL root, e.g. rtl/chip/rondo_regs.v> <module> [N] [depth]` -> reports/mutation_<job>.md (usage line corrected in the check round).
* Structural checks: `verif/formal/struct_checks.sh [RTL_ROOT]`.
* Pre-fix runs: add `--prefix` (uses build/verif/rtl_prefix and `-DPREFIX` where a harness needs it).

## 2. Formal with JasperGold (UNTESTED HERE)
* Same RTL, same harness files, same top, same defines: `verif/formal/jg/<job>_<task>.tcl` are generated by `gen_jobs.py` from the same tables as the `.sby` files.
  Each script: `analyze -sv12 -define FORMAL ... <rtl and harness>`, `elaborate -top <harness>`, `clock clk`, `reset -none` (the harnesses reset themselves with an `init`
  register), `set_prove_time_limit 4h`, `prove -all`, `report -summary`.
* Run: `VERIF_ROOT=<repo> verif/formal/run_jg.sh [--prefix] [<job>_<task> ...]` (set `JG=jaspergold` if the binary has another name; `JG_PAR` = parallel sessions). Logs in build/verif/jg/.
* Harness conventions that make the property files tool-neutral: every free signal is a module input (no `(* anyseq *)`/`(* anyconst *)` attributes; anyconst = input plus a stability assumption),
  properties are clocked immediate `assert/assume/cover` in `always` blocks with explicit history registers (valid SVA subset in JG), initial values on `init` registers.
* Expected output: all `assert` proven (or bounded-proven with a stated bound), all `cover` covered, `canary_*` and `mutant_*` scripts show at least one falsified assertion.
  Expected JG engine behaviour: PDR/Hp engines should close `regs`, `arb`, `kat` quickly; `seq`, `tile`, `dev_bus` unbounded proofs are not guaranteed (they need strengthening invariants if the engines do not converge).
* Risks to check on first use: (1) `-define NAME=value` syntax of `analyze`; (2) immediate assertions inside `always @*` are treated as combinational properties (intended); (3) JG may warn about the unconnected
  `init` initial value: use `reset -expression {init}` if the tool wants an explicit reset.
  (check round) (4) `reset -none` relies on JG honoring the declaration initial values (`reg init = 1'b1`); if it does not, every register starts free and the
  proofs see spurious states. Confirm on first use (e.g. the canary and cover results must match SBY); otherwise turn `init` into a harness input driven by `reset`.
  (5) `+incdir+$RTL_ROOT/rtl/chip` is now passed and the include-only `rondo_kat_sigs.vh` is no longer analyzed as a unit (needed by dev_bus: rondo_dev.v includes it).
  (6) `-define NAME=value` (GAPN=2, SPI_F_CRC=0) may need the `+define+NAME=value` form.

### JG-only full-strength versions (properties that SymbiYosys could not run at full strength)
| JG script | what is stronger than the SBY task | SBY status of the same property |
|---|---|---|
| spi_ctrl_jg_prove_full | unbounded proof of all spi_ctrl properties with payload free (no `SPI_F_DATA0`), CRC mode free (anyconst), GAPN 2 | SBY: BMC depth 34 (CRC off) / 28 (CRC on) only; PDR UNKNOWN; payload zeroed |
| spi_ctrl_jg_prove_gap1 | same at GAPN 1 (tightest legal byte spacing) | not run in SBY |
| spi_ctrl_jg_cover_full | all spi_ctrl covers with payload and CRC free | SBY: cover depth 160 at GAPN 4 (reached) |
| seq_jg_prove_unbounded | `seq` properties incl. prog1 (no-progress counter) unbounded | SBY: BMC 70 |
| tile_jg_prove_unbounded | `tile` properties unbounded | SBY: BMC 60 |
| dev_bus_jg_prove_unbounded | integration harness unbounded | SBY: BMC 60 |
| spi_phy_jg_prove_unbounded | `spi_phy` properties unbounded | SBY: BMC 200 |
Properties weakened for Yosys but shared as-is: none were rewritten; where SBY needs a bound the same file is proven unbounded by the `jg_*` task above. Concurrent SVA (`|->`, `##`) would allow
shorter property text in JG, but the shared immediate form is kept so one file serves both tools.

## 3. UVM with xsim (run)
* Build: `TOPSEL=DEV|CHIP verif/scripts/xsim_build.sh tb_top <cfg> [RTL_ROOT]` (cfg: S F S_TB2 S_MB S_SCAN_PG S_MIN S_ACC24 S_KAN S_CNT) -> build/verif/xsim/tb_top_<top>_<cfg>.
* Run: `verif/scripts/xsim_run.sh tb_top_DEV_S <test> <seed> [+args]` (own run dir with a private copy of xsim.dir; removed after the run). `COV=1` writes the functional-coverage DB.
* Regression: `verif/scripts/regress.py --tier smoke|nightly|signoff [--sim xsim] [-j N] [--prefix] [--cov] [--tests a,b] [--seeds 1,2]` -> reports/summary_<tier>.md.
* xsim-specific notes (kept out of the SV): the DPI model is built by gcc into `dpi.so` (xsc fails to link on this host); `uvm_hdl` and `uvm_cmdline_processor` are not usable (UVM_NO_DPI); `unique`
  constraints and `cover property` are not supported by xsim and are not used.

## 4. UVM with Xcelium (UNTESTED HERE)
* Script: `verif/uvm/scripts/run_xcelium.sh` (`build`, `run`, `one`, `merge`); `verif/scripts/regress.py --sim xcelium` drives it.
* Options used: `-64bit -sv -uvm -uvmhome CDNS-1.2 -timescale 1ns/1ps`, `-incdir` for the HardFloat/cfg/uvm directories, `-define CFG_<cfg> -define TOP_<DEV|CHIP>`, the DPI C file `verif/model/rondo_fpmodel.c`
  compiled directly by xrun (no separate gcc/xsc step; plain C with `svdpi.h` only is needed by the SV import), `-top tb_top`; `ACCESS=1` adds `-access +rwc`;
  coverage `-coverage all -covworkdir build/verif/xcelium_cov/<tag> -covtest <test>_<seed> -covfile verif/uvm/cov/xcelium_covfile.cf`; seed `-svseed <n>`; test `+UVM_TESTNAME=<t>`; seed tables `+CORE_DIR=.`.
* Coverage merge/report: `run_xcelium.sh merge <tag>` writes an IMC batch command file (merge all runs of the tag, `report -summary`, `report -html`) into reports/cov_xcelium_<tag>/.
* Expected output: `PASS tb_top_<top>_<cfg> <test> seed=<n>` lines, and the same UVM report summary (`UVM_ERROR : 0`) as xsim; the known failing test u_spi_abort (BUG-1) fails identically.
* Check round fixes: `build` now appends `_prefix` to the tag when RTL_ROOT is not the main tree (regress.py --prefix runs `<tag>_prefix`; before, it overwrote the fixed snapshot),
  and the PASS criterion also requires `TEST_DONE` (same as xsim). Also verify on first use: whether `-coverage/-covfile` are accepted (or ignored) at `-R` run time;
  the `deselect_coverage -betsoft` line in xcelium_covfile.cf (not a known flag combination; probably `-betf`); the IMC `merge ... -out` / `load -run` paths.
* Things to check on first use: `-uvmhome CDNS-1.2` availability in the installed Xcelium; the `rondo_hdl`-free design needs no `-access` for tests; unsupported-option warnings of the coverage file syntax;
  `$test$plusargs`/`$value$plusargs` use `+NAME` form (the script passes `+CORE_DIR=.`, `+NROUNDS=..` through unchanged).
